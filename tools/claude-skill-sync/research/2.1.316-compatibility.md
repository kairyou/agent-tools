# Claude Code 2.1.316 extraction compatibility

Investigated on 2026-10-31. Scope: extraction of the registered `code-review` and
`simplify` commands, with the repository's selected high-effort, Agent-enabled,
host-reporting-disabled variant. This note proposes an extractor change; it does
not promote a new upstream snapshot.

## Finding

The failure is a host-reporting selector change, not evidence that the prompt
text is missing. In 2.1.314, the review router receives a local selector initialized
by a direct predicate call. In 2.1.316, that selector is initialized by a comparison
between a separately computed reporting mode and `undefined`:

| Observation | 2.1.314 | 2.1.316 |
| --- | --- | --- |
| Agent selector | Direct predicate call | Direct predicate call |
| Host selector | Direct predicate call | Reporting mode is not `undefined` |
| Host predicate result | Used directly as selector | `"spawn"`, `"message"`, or `undefined` |
| Output formatter | Selected from host selector | Still selected from host selector |

These observations come from static inspection of the integrity-verified official
Linux x64 packages [2.1.314](https://registry.npmjs.org/@anthropic-ai/claude-code-linux-x64/2.1.314)
and [2.1.316](https://registry.npmjs.org/@anthropic-ai/claude-code-linux-x64/2.1.316).
The relevant minified reporting-mode binding in 2.1.316 is `B`, its selector is `j`,
and its predicate is `ot`. These names are evidence for this package only, not
identifiers to embed in the extractor.

The current extractor requires each router selector's initializer to be a
`CallExpression` with an identifier callee. The new host selector is a
`BinaryExpression`, so extraction stops at `Review runtime predicate changed`
before returning either skill. Existing static evaluation already supports strict
inequality and `void`; the missing behavior is recognizing how to constrain the
runtime mode from this selector. See [bundle.mjs](../bundle.mjs), especially
`extractOfficialSkills`, `StaticReader.eval`, and `StaticReader.binding`.

## Recommended change

Recognize the current upstream selector structure semantically at the router call
site. Keep Agent availability enabled through its resolved predicate binding. For
the router's host-reporting argument only, recognize the observed strict
inequality between an immutable local mode binding and `void 0`, resolve that
mode's direct predicate call, and supply `undefined` as
the predicate's symbolic result. Let the existing static reader evaluate the
comparison and formatter selection normally. Continue to select high effort and
the explicit fixes branch as specified in [RULES.md](../RULES.md).

Do not supply `false` as the new mode predicate's result: `false !== undefined`
evaluates to true and silently selects host reporting. Do not simply force the
router argument to false while leaving the output formatter's local selector
unresolved. The output formatter and fixes must use the same constrained selector.
These are consequences of the observed upstream comparison and the extractor's
separate evaluation of the output formatter before calling the router.

Keep this normalization narrow:

- Locate selectors from the registered command and unique effort router, without
  pinning minified names or prompt sentences.
- Require the verified comparison operator and an actual `undefined` expression.
  Do not classify every binary expression as a runtime predicate.
- Resolve the compared mode through immutable bindings to a direct identifier
  call. Reject writes, duplicates, cycles, ambiguous imports, computed calls,
  optional calls, spread arguments, and unrecognized wrappers.
- Preserve shared predicate identity. In the current fixture, the Agent predicate
  is reused by `simplify`, so review-only local substitutions do not establish the
  selected simplify variant.
- Retain the interpretation budget, unsupported-expression errors, and the ban on
  executing upstream JavaScript. No `eval`, `Function`, dynamic imports of the
  upstream package, runtime credential discovery, or live feature-flag calls are
  needed.

The binding and call checks are grounded in the existing reader's contracts and
tests, not an assumption that all upstream functions are safe. See
[bundle.mjs](../bundle.mjs), [the extraction tests](../../../tests/claude-skill-bundle.test.mjs),
and [the representative fixture](../../../tests/fixtures/claude-skill-bundle.txt).
The project policy in [AGENTS.md](../../../AGENTS.md) rules out adding a parallel
version-gated legacy implementation. Normalize the currently verified structure
instead of introducing a growing table of per-version extractors.

## Verification plan

1. Add a fixture for the observed reporting-mode comparison. Assert the selected
   review, output, fixes, and simplify texts, including absence of host-reporting
   output. A test that only asserts successful extraction would miss the false
   versus undefined bug.
2. Rename local symbols and move the exporting module. Extraction must still use
   the same semantic selector and import-resolution rules.
3. Add negative fixtures for an unrecognized comparison, dynamic or mutable mode
   binding, ambiguous predicate export, and unsupported wrapper. They must stop
   candidate generation.
4. Keep tests proving that selected upstream prose changes reach generated skills
   and that invalid or ambiguous output cannot be rendered. See
   [claude-skill-sync.test.mjs](../../../tests/claude-skill-sync.test.mjs) and
   [render.mjs](../render.mjs).
5. Run the proposed extractor against the real 2.1.314 and 2.1.316 packages, compare
   all four selected text hashes with the accepted snapshot, render both skills,
   and run the repository's check and tests. Real-package success is required
   before claiming compatibility.

The repository's downloader verifies that integrity before reading the known
archive member `package/claude`; it neither installs nor executes the upstream
package. See [official.mjs](../official.mjs).

A scratch copy of the extractor was tested against both integrity-verified
packages. It added only the host argument's observed strict-inequality case,
required the right operand to be `void` applied to literal zero, required the
left operand to resolve to a direct predicate call, and substituted `undefined`
for that predicate result. The Agent override and other extraction gates were
unchanged. Both versions extracted successfully. All four selected upstream text
hashes were identical to the accepted 2.1.293 snapshot:

The accepted baseline is [upstream/current.json](../upstream/current.json), and the
rendering rules are [render.mjs](../render.mjs). The experiment's scratch files
were kept outside the repository under the system temporary directory. This is a
real-package proof of the narrow approach, not a production change or a promise
that future predicate shapes are supported.

Separately, the unmodified extractor handles the direct-predicate fixture, while
wrapping that selector in `await`, boolean coercion, or a conditional reproduces
its explicit predicate-shape rejection. Those fixture experiments illustrate the
existing boundary; they are not evidence that those wrappers occur in 2.1.316.
The actual observed change is the reporting-mode comparison described above.

The scratch prototype also handled a fixture with a separately computed mode
compared with `void 0`, yielding all four original fixture texts unchanged.
Replacing that comparison with loose inequality, comparing with `null` or an
unknown identifier, or evaluating a call beneath `void` each failed closed.
These experiments cover the intended comparison shape. They do not establish
mutable-binding, optional-call, or spread-call safety. In the current reader,
overrides are checked before the ordinary mutable-binding guard, so the production
normalizer must validate those conditions explicitly before installing an override.
See `StaticReader.read` and `extractOfficialSkills` in [bundle.mjs](../bundle.mjs).

Production implementation, committed regression fixtures, and normal test checks
remain separate work.
